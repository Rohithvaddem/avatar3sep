DESIGN SYSTEM, VERSION 3, REVISION 1
One system for every screen, forevery role.
RDS v3 is the single source of truth for how Realtified looks and behaves.
Every colour, size, space and shadow is a token in one :root block. Every
com ponent is drawn only from  those tokens. Change a token and the
whole file restyles.
1Overview and principles
HOW TO USE THIS FILE
Start with the tokens (section 2), then the primitives (sections 3 to 7). Everything after that
composes them into cards, search, compare, listing blocks and every role's console.
Class names are BEM-like and prefixed rt-. All colour comes through var(--rt-…);
there is no literal colour outside :root. A standalone copy of the CSS is in rds-v3.css.
The seven product principles the components encode
1. Every buyer-facing fact carries a source tag (TS-RERA, Developer, Estimate,
Visited, Public record). On fact rows the tag sits right-aligned on the value line. In
tight 2×2 grids it becomes an icon-only tag with an aria-label. "Not yet verified"
uses the issue colour: "RERA no. not yet verified". Unknown numbers are
[PLACEHOLDERS], never invented.
2. One primary action per region. Raspberry is used only for primary buttons.

Writing rules
DO
Write from the buyer's side, in plain Indian English: "We share your number with the
developer only when you say so."
Name the source: "From the developer's TS-RERA filing, updated 3 Sep 2026."
Say "Developer" for the role, "Advisor" for our person, "home" for what they buy.
Use brackets for anything unknown: [ADVISOR NAME], [LEADS THIS WEEK], [CLIENT
NAME].
DON'T
Never use payment-holding language. Never show YouTube.
No jargon in labels ("Match Relevance Score": say "Recommended").
No "Photo not yet published". Show the locality map tile.
No invented stats, names of real people, reviews or ratings. No emoji. No pre-ticked
consent.
Legal line (footer): Realtified is a brand of Rudravatar Properties Private Limited, CIN
U68100TS2025PTC196506, TG RERA registered agent A02400005101.

8Cards
WHEN TO USE / RULES
There is one ProjectCard. Its slots never change: media, badge layer, title block, price
block, key facts, source tag, meta row, status pill, actions. A context (rt-card--discover,
--saved, --owner and so on) decides which slots show and what the meta row carries,
so the hierarchy follows what that viewer needs first: a buyer's saved card leads with what
changed since they saved; a developer's card leads with what needs their attention; a
reviewer's card leads with what they must decide. Never build a second card. In any list of
cards the buttons are secondary or quiet; the page keeps its single raspberry primary.
The anatomy: one card, nine slots
The shared markup. Every context below is this markup with fewer or different slots filled.

HOW THE LOCATION BLOCK WORKS
The list is the way to explore; the map supports it. Pressing a place (click, tap or Enter)
does three things: highlights its row and its pin, draws the road route from the project to

on it. The product opens with the nearest place already selected. The product draws the

view, so there is no satellite toggle. The tiles drawn here are an illustrative stand-in; a light
basemap in these cool neutrals (a Positron-style tile) is recommended so the pins and
the route sit on a quiet ground.

under group headings, each sorted by distance, and "Show all [N]" ends it. Distances and drive times are
